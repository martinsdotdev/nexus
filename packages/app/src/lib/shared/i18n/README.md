# shared/i18n

Thin wrapper over the generated Paraglide runtime (`$lib/paraglide`). Other code imports locale helpers from here, never from `$lib/paraglide/runtime` directly, so the generated path stays an implementation detail.

## Public API

```ts
import {
	availableLocales, // readonly Locale[]
	currentLocale, // () => Locale
	isSupportedLocale, // (value: unknown) => value is Locale
	switchLocale, // (value: unknown, options?: { reload?: boolean }) => void | Promise<void>
	localeOptions // () => { code: Locale; label: string }[]
} from '$lib/shared/i18n';
```

A future locale-switcher widget (editor toolbar) maps `localeOptions()` to buttons, marks `currentLocale()` active, and calls `switchLocale(code)` on click. `switchLocale` writes the `PARAGLIDE_LOCALE` cookie and reloads by default, so the caller needs no manual cache invalidation.

## Using messages

Messages live in `messages/<locale>.json` (flat JSON, `plugin-message-format`). Keys are namespaced with dots (`app.name`, `meta.locale_name`); access via bracket notation because the generated accessor preserves the dot:

```ts
import { m } from '$lib/paraglide/messages';
m['app.name'](); // "Nexus"
```

Convention: `lower_snake` within a segment, dot to namespace (`app.*`, `meta.*`, later `editor.*`, `overlay.*`). One file per locale; `messages/en.json` (the `baseLocale`) is the source of truth and every other locale must define the same keys.

`src/lib/paraglide/` is generated by the vite plugin from `project.inlang/` and is gitignored. It regenerates on `dev`, `build`, and `svelte-kit sync`.

## How to add a locale

Example: adding German (`de`).

1. In `project.inlang/settings.json`, add the code to `locales`: `["en", "de"]`. Leave `baseLocale: "en"`.
2. Create `messages/de.json` with the same keys as `en.json`. Set `meta.locale_name` to `"Deutsch"`.
3. Add the label to the `labels` map in `locale.ts`, pinning the locale so it renders as its own self-name regardless of the active locale: `de: m['meta.locale_name'](undefined, { locale: 'de' })`. TypeScript fails to compile until every `Locale` has a label, by design.
4. Run `pnpm -F app dev` (or `check`) once so the vite plugin regenerates `src/lib/paraglide/`.
5. Callers of `shared/i18n` need no change: `localeOptions()` and `switchLocale()` pick up the new locale automatically.

### If the new locale needs SEO-friendly URLs (`/de/...`)

That is a separate decision, out of scope for the current cookie-only strategy. It requires adding `"url"` to `strategy` in the generated runtime config, reintroducing a crawler-discovery block in `+layout.svelte` (a hidden `<a href={localizeHref(...)}>` per locale so the prerenderer finds each URL), and likely per-locale `entries()`. Revisit when a public multi-locale surface is actually shipped.
